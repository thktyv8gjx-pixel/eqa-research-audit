## 修复内容

新实现为 [bounded_resume.py](scripts/bounded_resume.py)，仅使用本机已有 Python 标准库，没有安装依赖。此前两个下载脚本和失败账本未改动。

| 环节 | 当前行为 |
| --- | --- |
| 每次请求之前 | 先将整个有界响应的字节预留写入追加式账本并 fsync，之后才连接 |
| 逐块接收 | 每块最多 64 KiB；`BODY` 字节数及 hash 入账并 fsync，再写候选文件并 fsync，最后记录 `COMMIT` |
| 正常中止 | SIGINT/SIGTERM 只设置停止标志，排空当前最多 1 MiB 的有界响应并结算后停止，不启动下一段 |
| 短响应、超时、强制退出 | 请求的完整预留继续计入保守预算；未决接收量不填 0，不由磁盘长度反推 |
| 断点续传 | 从最后已提交的连续文件偏移开始；累计接收量、已提交文件字节和预算计费分别记录 |
| 旧前缀保护 | 仅以只读方式验证和复制，追加发生在新目录的候选文件；原前缀不追加、不重命名、不删除 |
| 防并发与链接 | 非阻塞独占 flock；候选文件 O_NOFOLLOW、inode / hardlink 检查；第二进程在联网前拒绝 |
| 响应准入 | 必须 206、精确 Content-Range / Content-Length、固定强 ETag、identity 编码和预期类型；不跟随重定向或接受 200 回退 |
| 重试 | 不自动重试。后续显式续传使用同一账本及剩余保守额度；重复收到的字节不减免 |
| 文件和账本异常 | 前缀/候选 hash 变化、截断/篡改账本、已写未提交尾部等情况停止，保留材料，不自动截断修补 |
| 远端执行门 | 默认仅允许数字 loopback 地址；生产模式锁定唯一官方 URL 和文件身份，还要求新的明确批准记录 |

账本使用序号、前项 hash 和逐项 SHA-256 链以发现损坏；它是本地一致性校验，不是具有外部签名的防篡改证明。文件 hash 验证先于继续传输，最终完整 MD5 匹配才可将候选标为 VERIFIED。

## 计量口径与限制

成功排空的合法响应，`observed_body_bytes` 是已持久记录的 HTTP `read1()` 交付字节；它与该响应的声明长度核对。若请求异常或强制退出，最后一次 read 返回与账本 fsync 之间仍可能存在未记录字节，此时该字段只是下界；`charged_upper_bytes` 保留整次请求预留，作为继续请求的预算依据。

socket/TLS 预读、HTTP 头、DNS、TCP 重传与线路总流量未计量。报告不会把上述应用层口径称为线路精确计量。面对不合协议的响应，客户端在读取正文前拒绝，并停止后续请求；不能据此宣称服务端没有向网络发送数据。

正常信号行为在 `run()` 的网络阶段经过测试。初始化复制前缀阶段若被强制打断，不保证完成正常结算，但此时尚无媒体请求；未完成副本会在恢复检查中被拒绝。测试使用进程硬退出模拟故障，没有模拟真实断电、损坏硬件或远端 TLS 故障。

当前信号停止可能需要等待正在进行的≤1 MiB 响应排空或读超时，不能再次以强杀进程作为常规切换方式。强制退出仍可能留下不确定性，但该不确定性被保守计费并可能阻止继续传输。

## 测试结果

最终 run3：**26 项测试方法通过，0 失败、0 错误**，包含 14 个真实 SIGINT/SIGTERM 子场景、4 个强制退出窗口和 11 类响应协议错误。全部 97 次请求只连接 `127.0.0.1`，传输的是本地产生的 65,659-byte 合成数据，没有使用真实视频前缀作服务端载荷。
