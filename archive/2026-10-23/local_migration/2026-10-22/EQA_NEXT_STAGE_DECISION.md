# EQA 下一阶段候选决策

任务启动 2026-10-22，跨日完成/检索截止 2026-10-23（Asia/Shanghai）。仓库基线 `e8627bc729579268cb6c54cdb00f6a484f3e8ede`。本报告重新决策，不把历史 D1 优先排序当作前提。

## 决定

**唯一优先候选：D3 的小规模证据可定位性与复现准入验证。** 不是批准“做一个新视频记忆算法”，也不是确定论文题目。先判断：在明确的因果前缀、全链存储/处理预算和合法视频条件下，能否可靠识别“预算选择漏掉已可见支持证据”，并排除版本、权限与识别错误。若做不到，D3 也停止，不能以算力低为由降低证据标准。

| 方向 | 当前判断 | 核心理由 | 下一阶段地位 |
| --- | --- | --- | --- |
| D1 行动可恢复性 | **HOLD**，宽泛创新主张不成立；严格问题尚待证明 | 强直接近邻；缺同状态分支/预算见证；Mac 无已核实交互栈 | 不继续 PTP，等待资源条件发生实质变化 |
| D2 固定容量跨题干扰 | **保留、未准入**；不是已确认创新 | HIMM/GSMem/FAST-EQA 及新长期记忆工作已覆盖大量机制；缺公平容量/生命周期契约 | 暂不并行投入 |
| D3 视频前缀与证据保留 | **优先准入验证，尚未研究 READY** | 可绕开闭环仿真，证据可用小片段人工查验；但 SelectStream/WRWS 已直接覆盖宽泛主张 | 唯一优先，先过下述门槛 |

优先级依据是“用最小合法资源尽快证伪候选”的价值，绝不是“D3 最有创新”。当前三个方向都不能获创新认证。

## A. D1：缺失证据的行动可恢复性

**最近邻和已经解决的部分。** APED 已实现基于缺证据与歧义的观察/澄清选择；AbstainEQA 提供拒答任务与部分支持/原因标注，但高级策略是其未来方向；PTP 已做逐步探索校准，Pred-EQA 定向预测与补证据，HFLEX 具有检查物体/找房间/信心停止。GSMem 的记忆再渲染也威胁“重看丢失细节”的宽泛主张。来源和静态行级证据见历史 `NOVELTY_COUNTEREVIDENCE.md`，本轮未重新跑它们。

**仍待核实的差异。** 在同一完整状态、已声明合法动作与剩余预算下，为可恢复给真实见证链，为不可恢复给范围明确的覆盖/约束证书，并区别历史已见但记忆链丢失、感知/推理错误与真实意图歧义。尚无证据证明该差异是足量失效、未被已有方法覆盖，或能形成有效方法贡献。

**公开资源。** PTP 固定 JSON/QA 和代码、AbstainEQA、3D-Mem/OpenEQA 提供局部入口；HM3D 等需场景许可。PTP 单条审查已完成且 PARTIAL_ONLY，图片/坏前沿不是动作反事实。APED 论文不等于已有可下载完整逐步轨迹。

**Mac 可执行性。** 文献与 schema 审计可 CPU；闭环、同状态重置、成本记账与多分支取证在本机未验证。历史 Linux/CUDA/EGL 依赖使原样复现不成立，不因 M5/24GB 就放行。

**最小验证方案（只规划）。** 只有取得合法交互资源并验证可执行性后，固定一个可完整重置的小场景/任务，记录 H_t/M_t/R_t、控制器与随机状态、动作集合、成本与剩余预算；独立核验支持集合，再比较一次重检索、一次合法重观察、阈值校准及已有观察/澄清决策。负例只能在声明范围内作证。不能由未执行动作的模型预测替代结果。

**淘汰/继续 HOLD 条件。** 没有同状态分支/预算见证则 HOLD；若严格差异已被近邻实现、简单替代已解释收益、不可恢复标签无法可靠产生，或只能增加动作/未来真值获益，则终止方法候选。后续动作是资源申请条件登记，不重复 PTP 审查；本轮不向导师发消息。

## B. D2：固定容量跨题记忆干扰

**最近邻和已经解决的部分。** Sequential-EQA 已保留跨问题状态；MemoryEQA 已研究 k 敏感性/自适应检索。HIMM 跨 episode 召回并用视觉核验旧记忆、蒸馏可复用规则，不能只叫“旧笔记”而忽略。GSMem 以持续 3DGS 与多层检索恢复旧细节；FAST-EQA 明示固定容量假设集。MeMoREval/APM-Bench/DialogMem/BetaMem 进一步覆盖选择保留、证据不足、记忆形成/检索和预算契约。

**仍待核实的差异。** 在同一 canonical 问题序列/场景/初始 pose、相同全系统存储与读预算下，早题证据是否因容量挤占或实体/时间错绑定伤害后题；须排除场景组成、状态生命周期、遗忘与视觉推理混淆。HIMM 的 top-k 检索、GSMem 的局部优化窗与 FAST-EQA 的假设容量都不自动等于全系统字节严格有界，但“它们没解决此严格版本”目前也未获证明。

**公开资源。** [Sequential-EQA](https://github.com/jangablox/sequential-eqa) canonical 序列与 adapter、[MemoryEQA](https://github.com/memory-eqa/MemoryEQA) 实现可作为来源；按旧报告冻结 50 场景/498 题，原始生成 seed/源数据 revision 未保留，不能自行重新 shuffle 冒充原划分。HIMM/GSMem 已读论文不是已获得实现；GSMem [作者页](https://vulab-ai.github.io/GSMem/) 主要为论文和演示。

**Mac 可执行性。** 静态序列/容量契约可 CPU；完整多架构持久化比较依赖 Habitat、地图、编码器和模型，未核实本机端到端可用。GSMem 3DGS 路径尤其不能以普通 MPS 支持代替其 CUDA/渲染依赖审查。

**最小验证方案（只规划）。** 先冻结发布序列及文件 hash，列清场景/问题状态的保留与清除范围，定义总字节预算（含图/语义特征/索引/旧帧与外部缓存）和读 token。若有合法的少量既有完整观测，作顺序相同的 replay，比较 reset、原持久化、FIFO/LRU、均匀/多样性、top-k；全历史只作非等预算诊断。记录支持证据留存、错检索、错绑定与回答。此 replay 不能声称主动探索收益；闭环另需资源准入。

**淘汰条件。** 同预算/同生命周期下干扰不能复现；FIFO/LRU 足够；差异只是某 adapter bug；收益来自未计费外部全历史/额外调用；近邻已给等价机制及同类验证。若只能依赖大规模多栈仿真排错，当前本地阶段不推进。

## C. D3：严格视频前缀与有限预算证据保留

**最近邻和已解决的部分。** StreamEQA 已提供具身场景的流式视频 QA；SelectStream 直接研究固定容量图中的写入/整合/检索；WRWS 直接研究给定视觉预算下，何时检索历史、何时保留最近信息；OASIS 已采用分层事件记忆。仅加入历史帧/检索/不确定性/事件缓存，不足以构成新颖性。

WRWS 明确区分目标模型的有界输入与随视频增长的检索缓存，附录局限提出压缩/淘汰；其失败例也区分了“证据在输入但识别错”与“早期证据未选中”。因此不能把全链成本或这两种错误区分本身当新点。SelectStream 已有固定容量结构，所以“让 WRWS 缓存有界”也不能自动获创新。[WRWS 效率/失败/局限](https://arxiv.org/html/2609.37345v1)、[SelectStream](https://arxiv.org/html/2606.16353v2)

**仍待核实的差异。** 对 StreamEQA 具体时间/交互依赖，能否在协议一致且总缓存有界的条件下，定位可核验的支持证据丢失，并证明最近窗口、均匀、多样性、检索和已有有界方法不能解释剩余问题。当前仅为需要验证的诊断问题，没有提出新机制，也没有“窗口丢失是主因”的实测证据。

**公开资源与版本。** 本轮 GitHub API 确认 StreamEQA main 仍为 `01dc44aaef2a450ff245e9056fa39ee59bf75d5f`，与历史笔记相同。复查 README/video.py/Qwen3VL adapter/requirements：默认 64 秒窗口，窗口计算使用 realtime；视频裁剪有秒级取整，短/缺文件可跳过，约最多64帧。旧报告已发现该差异，本轮不把它重复计为新科研成果。

官方标注 3 文件的 Git 树大小：Perception 4,992,994 bytes、Interaction 8,525,036 bytes、Planning_all 10,483,686 bytes；本轮仅取目录元数据，没有下载这三个数据 payload。上游标注公开不等于已取得视频或逐题支持标注。[固定标注目录](https://github.com/MrYF-Wang/StreamEQA/tree/01dc44aaef2a450ff245e9056fa39ee59bf75d5f/data/annotations)

HD-EPIC 官方页标明视频 MP4 总量约115.5GB、VRS约1.9TB，CC BY-NC4.0；公开了注释和下载工具。当前不下载整包、不假定可按任意时间范围切出服务器片段，精确单文件大小、合法小样本获取方式与本地可用性仍需核。[官方资源与许可](https://hd-epic.github.io/site/)

**Mac 可执行性。** 元数据、人工少量视频查证和简单采样诊断比交互仿真更有可能在本机完成。现阶段 ffmpeg/torch/MLX/视觉编码器均未准备，官方 adapter 的 CUDA/CPU 路径不等于 MPS 可用。2B/量化模型只能作另列配置的工程入口，不能代替论文8B baseline 而声称精确复现。证据覆盖的 CPU 人工核验可在模型准入前完成。

**最小验证方案（未执行）。** 在合法小片段和字段联结通过后，先选2–3个不同视频、最多12题作“是否能判别”的人工可行性检查，选择规则在看模型预测前固定，保留全部未知/跳过项。这不是效能估计样本或论文实验。固定 tq，逐题登记允许前缀、事件起点是否使用评测特权、支持证据时间段及可辨程度；区分前缀内有支持/没有支持/无法判定。未来帧只能用于独立离线核验，不能进入策略或阈值选择。

在人工 gate 通过、依赖和模型另获准入后，才比较最近窗口、全前缀等帧均匀采样、多样性、简单检索及最近邻可复现配置；同一模型、dtype、分辨率、视觉 token/帧预算，另计总缓存字节和全部解码/外部编码成本。支持 oracle 只是诊断上界。记录证据留存但答错、选择漏证据、真值/时间不明、运行失败各自分母。不得把离线 replay 写成真实机器人闭环改进。

**淘汰条件。** 支持证据不可可靠定位；小子集无法合法独立取得；差异只来自64秒/事件起点/取整/漏样本；简单均匀/最近窗口已解释全部问题；近邻覆盖同一严格设置；收益来自未来真值、额外编码/外部缓存或额外帧；本机成本只能靠不可接受的配置才能完成。协议差异修正可作为复现记录，不能升级成算法贡献。

## 唯一下一任务及准入条件

任务名称：**D3 小样本证据可定位性准入**。目的只是决定是否值得做真实小规模复现，避免先写算法再寻找失败。

进入该任务前需要满足：

1. **资源合法可控**：明确 HD-EPIC 的具体文件/片段、许可、精确大小/总上限、独立获取方式及本地位置；若只能全量大包下载，停止在资源登记层。现有“你自己干完”授权的是完成本轮报告，不扩展为大型下载/训练许可。
2. **协议和版本清楚**：锁 StreamEQA commit；逐题联结 video ID、tq 与事件区间；标清论文事件起点、代码最近窗口和独立全前缀诊断三种不同权限，保留官方结果口径，不修改官方脚本。
3. **可辨识差异**：先补读与此具体设置最接近的 WRWS/SelectStream/APM-Bench/OASIS 相关方法与预算契约；若等价问题已经有充分验证，直接淘汰方法候选，无需为 Mac 另造论文题目。
4. **证据可人工判定**：以预先固定的小样本规则登记支持和未知，不能用答案文本或生成 caption 冒充视觉真值。若该条件失败，D3 不进入模型实验。
5. **执行环境单独过门**：以后需要模型时，先审核依赖并建立独立 Python3.12 arm64 环境；小型 MPS/CPU数值测试和具体模型 forward 成功、无静默设备回退、内存/时间可接受后，才能申请小规模复现。当前此条件未通过。

下一任务交付应为小样本来源/权限与时间联结记录、支持证据可判定性记录、近邻覆盖差异及 GO/HOLD/STOP 决定。不得输出未经执行的性能表。若 gate 通过，再由一份单独的复现协议约定样本量、开发/测试分离、视频级配对统计、实际效应精度及成本；不先许诺提升百分比或仅凭12题宣布有效。

## 本轮终点与执行边界

本轮完成的是四份迁移/环境/研究状态/路线报告。没有训练、模型推理、大型数据或模型下载、云GPU、付费API、完整 benchmark、Habitat 仿真、官方协议修改或 GitHub push。没有把 PTP 已完成审查重新排成待办，没有把暂缺原件写成从未存在，没有因为 M5 的硬件条件而降低新颖性或证据要求。
